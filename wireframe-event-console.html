What the numbers mean

1
Status pill. Booth readiness at a glance — amber while setup is incomplete, green once all four steps are ticked. Driven by the checklist, never hand-set.
2
Event strip. Name, date, location and mode collapse into one horizontal band. Replaces the tall dark card; the sidebar already shows the same event, so it is not repeated at full size.
3
Visible edit. A plain "Edit event" button. Replaces the corner ⓘ icon, which reads as help text rather than an action.
4
QR hero. Largest object on the screen, candidate-facing headline above it. A student walking past should understand the screen without asking anyone.
5
Destination shown. The URL the QR points at is always visible with one-click copy. Today it hides behind a modal — a recruiter cannot verify where the code sends people.
6
Four actions. Copy link (primary), print poster, open form, and a new Test scan so the booth can be verified before the hall fills.
7
Booth pulse. Live capture stats for this event only: scanned today, open follow-ups, time since the last scan, and a jump into AI Review.
8
Intake destination, inline. Method + URL edited in place with a Test link action. No modal, no lost context; the QR re-renders on save.
9
Setup checklist. Four steps a recruiter ticks off at the booth. Progress feeds the status pill and gives the page a job beyond static info.

Changed from today's page

  • Event card → strip. Dark 420px card with redundant copy ("Quick candidate capture…") becomes a one-line identity band.
  • Modals → inline. Both ⓘ editors become visible controls; nothing to discover.
  • QR moves left and grows to a 252px hero; the right side becomes a working rail instead of a second display panel.
  • Destination URL surfaced under the code with copy, instead of living only in settings.
  • Added: setup checklist, booth pulse, test scan, open form.
  • Removed: duplicated "Scan to Submit Profile" shown twice around the same QR.

Interaction spec

  • Copy QR link → clipboard + toast "QR link copied". Same label in button and toast.
  • Save destination → re-render QR, toast "Booth QR settings saved.", state chip stays "Connected".
  • Test link → opens the URL in a new tab; failure keeps the previous URL and says so.
  • Checklist → optimistic toggle, persisted locally; pill flips to "Booth ready" at 4/4.
  • Test scan → routes one test submission into AI Review flagged as a test, so it can be discarded.
  • Print poster → print stylesheet hides chrome, prints QR + event + URL at poster scale.
  • Escape closes any inline editor; all actions keyboard reachable with visible focus.

Open questions

  • Should the pulse read this event only, or all capture today? Booth context argues for this event.
  • Is Test scan worth a slot, or does it belong in the destination card as a secondary link?
  • Does the checklist persist per event, or reset each fair morning?
  • Confirm QR minimum printed size for the poster so the on-screen 252px matches physical scan distance.

Mobile rules

  1. QR first. On a phone the code is the reason the page exists, so it sits above event details.
  2. Actions stack full-width for one-handed use while holding a conversation.
  3. Stats collapse to three columns with the review link as a full-width row underneath.
  4. Rail cards flow below the hero instead of sitting beside it — no side-scrolling at the booth.
  5. Print stylesheet strips the sidebar, topbar, checklist and stats, leaving QR + event + URL.
  6. Same content order as desktop, only stacked: identity → QR → pulse → setup.
